## 使用

- 当前复位默认四画面（M=0）；双摄融合（M=5）左图=摄像头2（ID1），右图=摄像头1（ID0），摄像头3/4继续原始采集和DDR写入。
- Key1低有效，每次按下循环：四画面→相机1→2→3→4→双摄融合→四画面。持续按住不连发。
- Key2低有效，短按松开按当前方向改变D一个源像素；保持1秒翻转方向一次，松开不附加短按。双触发器同步，连续20ms消抖。复位默认增加，范围0..1278饱和。
- 顶层参数`D_DEFAULT=256`可覆盖；256只是初值，没有实测标定。上电首套参数尚未准备或缺任一源图时，桥显示黑色并统计中止。
- 模式仅在旧会话结束、桥排空后的新光栅VS请求中生效。D经参数准备后在新融合会话边界提交；准备期间继续用旧完整配置。单摄时按键也能改变pending D。
- 保持50MHz、1650×750总光栅，1280×720有效画面。HDMI/摄像头I²C源选择、后级处理、PCIe保持原路径。

## UART终端与协议

新增独立顶层输出 **stitch_uart_tx**，原`uart_txd/uart_rxd`接口保留。用户自行完成新TX约束。终端设为115200、8N1。现有发送器每bit周期为floor(50000000/115200)+1=435个时钟，按理想50MHz约114942.53baud，不是实测频率。

每秒请求输出一组；按键pending/方向/模式、活动几何、错误计数或sticky变化触发补充组。状态每100ms请求/应答采样，高频事件合并，每组起点至少相隔100ms，忙时仅保留最新快照，不反压视频。UART字节间uart_state变低不视为整包完成，必须等待Tx_Done。组内8条ASCII记录均CRLF结尾，最长29字节，小于32字节上限。

```text
CFG M={1hex} P={3hex} A={3hex} DIR={+/-}
GEO H={3hex} T={3hex}
SEQ L={8hex} R={8hex}
ERR UF={8hex} AB={8hex}
STA FV={1hex} OV={1hex} WD={1hex} PE={1hex}
DDR RD={8hex} WR={8hex}
EXT RE={8hex} CE={8hex}
PAR CP={1hex} GV={1hex}
```

| 字段 | 含义 |
| --- | --- |
| M | 最近接受的显示会话模式，0四画面，1..4相机，5双摄融合 |
| P / A | 最新视频域待提交D / 最近提交的活动融合D；单摄时A保留上次提交值，提交后缺图也不表示已成功显示 |
| DIR | 当前按键调节方向 |
| H / T | 活动参数bank有效高度/上黑边；没有活动配置时为0 |
| L / R | 最近成功锁定的相机2/1帧序号，不代表同步曝光 |
| UF | 桥WAIT_FRAME/RUN离开时的FIFO空事件数；排空期间不累计 |
| AB | 桥消费的abort记录数，包括无配置、无完整图和读故障；纯欠流后成功排到EOF不额外算abort |
| FV / OV / WD | 四路完整帧掩码 / 采集溢出sticky / 写丢帧sticky，bit0..3=相机1..4 |
| PE | DDR协议错误sticky（低bit有效） |
| RD / WR | DDR读/写128位拍累计数，不是字节或帧数 |
| RE / CE | 融合会话因行读错误中止次数 / 有效图像区两路覆盖均无效的像素计数 |
| CP / GV | core观察到的待提交配置状态 / 活动几何有效。P在video域采样，CDC传播期间P与CP可能短暂不一致 |

所有数字均固定宽十六进制；32位计数自然回绕，按模2^32差分。读取不清除sticky或计数。视频域与核心域快照有时间差，不可用串口推断同时曝光。串口不会发送整幅图像，也不接受控制命令。

## 资源、吞吐量与边界

行缓存载荷为8×1280×16=163840bit（20KiB），分成16个640×16奇偶列RAM；权重两bank共23040bit（2880字节）。实际RAM块、DSP、逻辑占用及最高时钟未知，必须以用户工程实现报告为准。

缓存命中时逻辑可每core_clk接受一组双路邻域；端口独立、同步读输出受弹性握手控制。每个DDR突发仍先捕获2048位，再128周期逐像素解包；行加载、四写一读轮询、DDR延迟、缓存缺失及背压会降低持续速率。保留4096像素输出FIFO，不宣称当前缓存深度/仲裁已保证40.404fps。出现UF应结合RD/WR/RE、sticky与调试信号定位，不关闭3/4路或静默降低时序。

双槽锁定可能导致采集丢帧；两路锁定只保证帧内一致，不能保证同步曝光。双线性缩小没有完整抗混叠滤波；不做曝光匹配、畸变/透视校正或深度视差补偿。帧中故障只能将后续光栅置黑并排空，已经输出的像素不能回滚。

继承DDR端口限制：若DDR永久不返回last，不能安全释放在途读事务，需系统复位；不编造超时完成。正常可报告的mem_done/error路径会先清理行读再释放双槽。

## RAM复用更新（2026-10-27）

权重表和行缓存统一通过stereo_ram_read_hold实例化现有dualport_ram；公共RAM源码及接口未改。拼接模块不再直接声明像素或权重的大数组。adapter仅增加读结果保持寄存器及选择逻辑，补足公共RAM没有读使能的接口，正常读仍是一拍，背压时保持数据。

权重表使用4096×9 RAM，地址最高位区分两个bank，每bank仅使用前1280项；有效载荷23040bit，声明容量36864bit。行缓存仍为16个640×16奇偶列RAM实例。块RAM映射及stitch低于4000 LUT目标需重新综合确认，实例化模块本身不代表资源目标已通过。

参考3×3实现：两条历史行RAM加当前输入流，横向移位形成九个像素，并非九行缓存。当前拼接共8行，为双摄各2行插值加2行预取。每路减少到2行可保留双线性算法，但需重做预取/换行调度，可能增加DDR等待；本次保留行数。fifo_ram为顺序FIFO，不适合直接按缩放坐标寻址，因此选择dualport_ram。

解释与限制：

- UF直接连接`camera_fifo_empty_count`，在WAIT_FRAME/RUN的有效扫描拍发现FIFO为空时统计；进入DRAIN后不继续按像素累计。不是丢失像素总数，也不是全部失败原因之和。
- `cds_video_bridge.v`默认每拍输出黑色；只有WAIT_FRAME/RUN且FIFO有效、标记匹配时输出像素。欠载或标记不匹配进入DRAIN，继续消费至EOF/abort；即使数据随后恢复，本帧余下仍为黑色。AB=0不能排除这种失败。
- CE在坐标请求被接受、输出tag位于有效图像区且`c_meta[25:24]==0`时增加。已核对`stereo_coord_gen.v`：tag为[48:29]，左右覆盖为[25:24]，统计位段对应正确。**CE不是行缓存miss计数。** 目前没有定位到首个覆盖异常坐标，不能把它简单归因于DDR慢。
- WD是写入丢帧粘滞位；原因包括无可写槽、新SOF打断写上下文、帧长度错误和写事务错误。WD=F说明四路都曾触发，不提供次数/当前速率，也不能证明写入一直失败。
- M=0时没有融合请求，几何准备结果需等首次融合会话才提交，因此CP=1/GV=0/A=0不等于初始化卡死；CE=0/SEQ=0也不能验证融合正确。

- PE/RE为0仅代表对应逻辑未报告错误，不能排除像素错误、时序违例或其他链路问题。

### 当前代码中已识别的供数瓶颈

1. `stereo_frame_reader.v`为REQUEST→FILL串行结构：每突发读16个128位拍（128像素），完成后逐像素拆包128拍，再请求下一突发。每源行10突发，左右相机共用读取器。拆包期间没有下一读取请求，限制持续行填充速率。
2. `stereo_line_cache.v`仅在`req_valid && (|req_meta[34:33])`时启动行加载。顶部黑边两路覆盖均关闭，当前没有利用黑边阶段提前装载首批源行。
3. 行缓存总共八行（左右各四行），不是九行。双线性采样每路需要当前两行，其余用于下一组行预取。当前优先检查两路当前行，再检查下一组行；不能在仍被当前采样使用时覆盖对应bank。
4. `cds_ddr_port.v`四写一读轮询，整个端口最多一个未完成事务。读事务还有四路写入竞争；仅凭现有日志不能断定DDR物理带宽不足，也不能断定每次失败都由仲裁引起。
5. 输出为固定50MHz、1650×750总光栅，约40.4帧/秒；有效像素期间每拍消费一个像素。4096像素FIFO只能吸收有限停顿，不能补偿长期平均生产速率不足。

### 推荐实施方案（尚未实施）

#### 优先级一：补足定位信息，确认失败位置

现有桥已有`first_fault`、`marker_error_count`、`drain_frame_count`，但当前UART八条记录没有输出。先增加这些诊断，再根据需要增加FIFO最低水位、行缓存等待周期、DDR请求等待周期以及首个CE的tag/坐标/覆盖掩码。

`first_fault`布局为`{有效[31], state[30:29], FIFO有效[28], abort/EOF/EOL/SOF[27:24], x[23:12], y[11:0]}`。首次故障快照只在复位后首次异常锁存；必须结合复位后模式切换过程解释。

若首次有效图像附近就失败，重点看初始预取；若水位逐行下降，重点看持续供数；若marker_error增长，检查标记与像素对齐。新增计数不可直接把多位跨域总线接到UART，应沿用快照/握手机制。

#### 优先级二：提前预取，保持八行容量

双路源帧成功锁定后，即可加载左右各自首批两行，接着准备后续需要的行；允许与顶部黑边输出并行。默认D=256时60行黑边对应约1.98ms扫描时间，是可利用的准备窗口，但不是无条件保证可用的额外FIFO容量。D=0没有黑边，应单独验证启动策略。

保持当前采样缺失行优先，随后预取下一输出行所需源行；保留能复用的tag，不重复读取已有行，不覆盖仍被使用的bank。必须处理停止、清理和在途读取返回，不能提前释放源帧槽。

#### 优先级三：DDR下一突发与当前突发拆包重叠

使用两块突发缓冲交替接收/拆包，每块16×128bit=256字节。当前缓冲拆包时即可发起下一突发，先保持DDR最多一个未完成读取，不引入多事务乱序。

优先复用现有`dualport_ram`；但目前DDR接口一次提供2048位完成数据，RAM是单写端口，**不能把2048位数组机械替换成RAM就宣称完成优化**。需具体设计如何从128位返回拍或稳定完成缓冲搬运到RAM，以及两缓冲的所有权和发布时序，核算搬运是否又造成串行停顿。若调整DDR接口，须同时保持单摄、四画面和随机读取兼容。

接收完整且无错误后发布缓冲，拆包完成后才允许覆盖。同步RAM读延迟、像素地址、fill_valid与数据必须对齐。复用现有缓冲的可行性应先评估，避免额外增加两套2048位寄存器和大选择器，违背LUT目标。

#### 优先级四：有依据地调整仲裁

仅在前述改进后仍存在DDR等待瓶颈时，按输出FIFO低水位/必需行缺失提高读优先级，并结合采集FIFO高水位保护写入。保持有限连续服务次数，防止饥饿。若引入跨域水位信号，应安全同步；不可直接传递二进制多位水位。

不要永久读优先，不要关闭相机3/4写入，不要静默降低输出帧率。增大FIFO仅作为短时停顿缓冲的后续选项，不作为持续带宽不足的主要修复。
