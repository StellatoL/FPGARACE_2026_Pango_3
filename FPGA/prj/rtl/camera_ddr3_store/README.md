## 固定规格与地址

- 分辨率固定 1280×720；每像素 16 位；DDR 数据宽度固定 128 位，地址宽度 28 位。
- **地址单位是 16 位字，不是字节**。不要直接接到字节寻址的通用 AXI 总线。
- 通道基址 `camera_id × 0x200000`，槽偏移 `slot × 0x100000`。
- 每帧有效范围为槽内 `0x00000`～`0xE0FFF`，每帧共 921600 像素。
- 写入和顺序读取每个突发 16 拍，共 128 像素，地址增加 128；每行 10 个突发。
- 坐标读取为单拍突发，地址为 `base + slot_offset + y*1280 + (x & ~7)`。
- 最早像素放在 128 位拍的 `[15:0]`；下一像素放在 `[31:16]`，依次类推。
  原有宽窄 FIFO 的位序不参与本模块；需要后续仿真/上板核对 DDR 端到端位序。
- 四路合计预留 16 MiB，接入前确认没有其他 DDR 使用者占用这些地址。

## 摄像头输入与跨域

`cam_clk[0:3]` 是四个独立像素时钟；通道 n 像素连接到 `cam_pixel[n*16 +: 16]`。
`cam_vsync[n]` 的**上升沿**开始一帧，且该拍必须没有 `cam_de[n]`。
若采集模块使用另一同步极性，应在接入处转换。
`cam_de` 必须按光栅顺序提供每行 1280、每帧 720 行的有效像素。
本实现按有效像素总数计数，不使用 hsync，不检查每行 de 长度；超过一帧的额外
de 会被忽略。上游必须保证输入格式，不能用本模块代替摄像头格式检测。

四路输入都应取自原始采集输出，绕过 `camera_quad_reshape`，不要使用
`current_video_select` 或显示通道选择去门控任一路 `cam_de`。

每 8 个像素打包一个 130 位 FIFO 条目（128 位数据、SOF、EOF）。
默认 FIFO 深度 512 个条目，仍为每路 4096 像素约 8 KiB；另有预取和事务寄存器。
`FIFO_ADDR_BITS` 保持旧的“以 128 像素突发计容量”语义，默认仍为 5；
内部传给异步 FIFO 的地址宽度为 `FIFO_ADDR_BITS+4`。
core_clk 域的 cds_writer 收齐 16 个数据拍再发出一个 DDR 突发。
FIFO 溢出后不会产生尾标记；下一 SOF 会重新对齐，包括丢弃未组完的突发。
DDR 仍按 16 拍发送，不会因 FIFO 暂空而在事务中缺少写数据。
`FIFO_ADDR_BITS >= 2`，增加此值可吸收更长 DDR 服务间隙，但不能解决平均带宽不足。
FIFO 满时不能反压摄像头：停止接收该帧剩余像素，置位 `capture_overflow`；
不产生 EOF，因此半帧不会发布。下一个成功进入 FIFO 的 SOF 重新建立写上下文。
FIFO 不按每帧复位，避免破坏跨域指针一致性。

`reset_n` 应为系统复位与 DDR 就绪条件的组合，并用于整个子系统一致复位；
不得只复位 FIFO 的一侧，也不得在 DDR 事务尚未清理时单独复位本模块。
各域内部使用两拍同步释放。读接口所有输入和状态读取均应处于 `core_clk` 域。
跨域控制寄存器需要在上层使用可靠 CDC，不能直接接异步多位控制总线。

FIFO 采用双口 RAM 风格描述，存储阵列不复位，读数据寄存器通过 valid 保护。
实际 Pango 综合是否推断到预期 RAM、130 位宽的 RAM 利用率和多路选择时序，
需要在目标器件核对。若替换为厂商 FIFO，必须保留这里的 ready/valid 和预取语义。
为各时钟建立正确约束，并对 Gray 指针跨域路径设置目标工具支持的总线偏斜/最大
延迟约束，限制各 Gray 位传播差异；仅标记 ASYNC_REG 或仅设置 false path 不足以
保证物理 CDC 正确。复位释放也需纳入实现检查。

## 双槽规则

写端读到 SOF 才分配一个未锁定槽；优先选择最新完成槽的另一个槽。
如果这个槽被读者锁住，可以复用最新完成槽，但会立即将它标为无效，直到新帧完成。
这段时间新的读请求可能收到“无可选完成帧”错误；已锁定的读会话不受影响。
若没有可写槽，则丢弃该输入帧并报告 `write_drop`。
当前读侧只有一个会话，最多锁一槽；无可写槽分支保留了两个槽都受保护时的行为。

同拍读锁定优先于新写槽分配。帧中遇到 FIFO 溢出、缺失尾标记、突发数量不符或
DDR 长度/last 异常，不发布该帧。仅完成第 7200 个写突发且无错误时更新完成槽和
32 位帧序号。帧序号从 1 开始，32 位自然回绕，表示发布次数而非传感器曝光编号。
四路没有硬件同步时，相同帧序号不代表相同曝光时间。

## 顺序读取

所有握手均在 `core_clk` 上升沿以 `valid && ready` 为准。

1. 设置 `read_mode=0`，给出 `source_sel`，保持 `seq_valid` 直到 `seq_ready`。
2. 握手时锁存通道、完成槽和 `selected_sequence`，帧中改变 source_sel 不影响当前帧。
3. 无完成帧时，接受请求后产生一拍 `seq_done=1, seq_error=1`，不输出像素。
4. 成功时按行输出 921600 个像素。`pixel_valid && pixel_ready` 消费一个像素。
5. `pixel_sof/eol/eof` 仅在 `pixel_valid` 时有意义，分别标记帧首、行末和帧末像素。
   背压时像素和标记保持。帧末像素消费后产生一拍 `seq_done` 并解锁。
6. DDR 协议异常会中止当前顺序帧并产生 `seq_done=1, seq_error=1`；下游应丢弃已
   接收的部分帧。若控制器不再响应，模块等待到系统复位，不能保证错误脉冲一定出现。

`seq_valid` 一直保持为 1 会在每次回到空闲时请求下一帧。`seq_done/seq_error` 是脉冲，
调用方必须每拍观察。顺序读是可停顿像素流，不能直接当 HDMI 固定时序输出。
本工程已通过 cds_video_bridge 增加输出 FIFO、帧起点预取及欠流恢复策略。

## 坐标读取

设置 `read_mode=1`。`req_valid/req_ready` 接收 `{camera_id,x,y,req_tag}`，
`rsp_valid/rsp_ready` 返回 `{rsp_pixel,rsp_tag,rsp_error}`，`TAG_WIDTH` 默认为 16。
坐标范围为 `x<1280,y<720`；越界或无完成帧时不访问 DDR，返回错误及零像素。
一次最多接受一个请求；忙时 req_ready 为 0，调用方必须保持请求或在外部排队。
没有内部请求队列，因此不存在静默覆盖排队请求的行为。
响应背压期间数据、tag、错误和选定帧序号保持，锁定槽也保持到响应消费为止。
延迟可变，不承诺固定拍数。

每个坐标请求独立锁定最新完成帧。多次请求可能命中不同帧；后续需要一批鸟瞰
坐标固定在同一帧时，应扩展显式 begin/end 会话接口，不能假设当前请求自动共享锁。
`read_mode` 仅在空闲时决定接受哪类请求；帧中改变模式不会取消当前会话。
顺序读和坐标读互斥，不会同时产生两个 DDR 读请求源。

## 接入当前 DDR IP

本模块匹配 `pcie_video.v` 中实际使用的 Pango 精简接口：

| 新顶层端口 | 工程 DDR 信号/接法 |
| --- | --- |
| `core_clk` | DDR 输出的 `core_clk` |
| `reset_n` | 系统复位有效且 `ddr_init_done` 有效 |
| `axi_awaddr/awlen/awvalid/awready` | 对应写地址端口 |
| `axi_wdata/wstrb/wready` | 对应写数据端口 |
| `axi_wlast` | `axi_wusero_last`，方向为 DDR 到本模块 |
| `axi_araddr/arlen/arvalid/arready` | 对应读地址端口 |
| `axi_rdata/rvalid/rlast` | 对应读返回端口 |
| DDR `axi_awuser_id/axi_aruser_id` | 固定 4'd0（本模块仅一个未完成事务） |
| DDR `axi_awuser_ap/axi_aruser_ap` | 固定 1'b0，或按当前工程已确认的配置 |
| DDR 返回 `axi_wusero_id/axi_rid` | 本实现不使用，单事务路由由仲裁器持有 |

此 IP **没有标准 AXI 的 WVALID、RREADY 和 B 响应通道**，不要将本模块视作标准
AXI4 master。要求地址握手之后才开始数据传输，写 WREADY 每次有效消费一拍，读
RVALID 每次有效返回一拍；本模块预先缓存整个突发，读返回永不反压。
`AWLEN/ARLEN` 为拍数减 1，写/顺序读为 15，坐标读为 0。

当前发布条件是最后一个突发的末拍被 IP 消费。本实现依赖该 DDR IP 对本端口
“已接受写事务之后发出的同地址读”的顺序一致性；因为实际工程没有 B 通道，
无法另行等待标准 AXI 写响应。集成时必须依据所用 DDR IP 配置/手册确认这项语义。
若换成有 B 通道的控制器，应修改适配层，以成功 B 响应作为写完成并传递错误。
DDR 校准、物理内存错误等不在此精简端口上反馈，不能由 transaction_error 检出。

只允许本模块驱动这些 DDR 命令端口；替换旧 framebuffer 连接，不能与其直接并联。
本次顶层已替换旧 framebuffer；旧文件保留但不再实例化。

## 仲裁、带宽和状态

四个写请求源和一个读请求源按突发轮询，全端口串行，最多一个未完成事务。
事务期间固定所属通道；请求数据保持到 done。完整缓存可容纳不可背压的返回。
为降低接口风险，未启用多 outstanding 或读写并行；实际效率须后续测量。
在四路 30 fps 且另外顺序读一路 30 fps 时，单计图像载荷约需 276.48 MB/s，
还未计入地址阶段、刷新、读写切换、FIFO 等待和其他开销，不能据此保证目标帧率。

| 状态端口 | 含义 |
| --- | --- |
| `frame_valid[3:0]` | 当前各路最新槽是否可用于新读请求 |
| `frame_sequences[n*32 +: 32]` | 通道 n 已发布的最新帧序号 |
| `capture_overflow[3:0]` | FIFO 满导致丢弃，已同步到 core_clk 的粘滞位 |
| `write_drop[3:0]` | 写上下文被新 SOF 中断、无空槽、帧长度错误或 DDR 写异常的粘滞位 |
| `protocol_error` | DDR 返回 last 与期望拍数不符的粘滞位 |
| `write_beats/read_beats` | 已传输的 128 位写/读拍累计值 |
| `busy_cycles` | DDR 仲裁器非空闲周期累计值（包含完成交接周期） |
| `request_wait_cycles[n*32 +: 32]` | n=0～3 为四路写，n=4 为读，req 保持期间的累计周期 |

粘滞位通过复位清除。所有统计计数器 32 位自然回绕，需用模 2^32 差值测量。
`request_wait_cycles` 包含传输和完成交接时间，并非单纯的仲裁等待时间。
时间窗内 `Δwrite_beats*16/Δt` 为实际写字节吞吐量，读取同理。
状态只提供观测能力，本次没有运行性能测量。

## DRM 资源优化（2026-10-14）

旧综合报告显示四路 32×2050 FIFO 被混合映射到分布式 RAM 和许多
32×72 的 DRM36K，宽而浅的布局造成较多 DRM 空间浪费。
本次改为 512×130，像素容量不减，数据拍在 core_clk 域重组。
四路输入、双帧槽、坐标读、KEY2 切换和输出 FIFO 深度均保留。
采集域打包寄存器同时从每路 2048 位降为 128 位。
相比旧实现，写端需用 16 个 core_clk 周期收齐一次突发，
相关吞吐量和跨域恢复仍须后续仿真/上板确认。
最终 DRM 占用以重新综合/Device Map 报告为准，不能用位数估算替代实测。
